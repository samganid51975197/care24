# 개인정보 저장 보호

## 적용 범위
Node/가비아용 소스 및 현재 PC의 시험용 DB에 적용. 기존 Cloudflare Sites 게시본과 가비아 운영 DB에는 아직 적용하지 않았습니다.

- AES-256-GCM, 필드·파일마다 무작위 96비트 nonce와 128비트 인증 태그.
- DB 필드의 AAD는 `테이블.열`, 파일의 AAD는 `upload:저장키`, 메타데이터는 `metadata:저장키`. 암호문을 다른 열이나 파일명으로 바꾸면 복호화 실패.
- 보호 대상은 `lib/protected-fields.mjs`. 주민번호가 포함된 요청 JSON 전체, 계좌번호, 주요 이름·연락처·주소·건강정보·서명·첨부파일 목록 등을 포함.
- 파일 내용과 MIME 등 메타데이터도 암호화. 공개 폴더 밖 저장, 서버에서 소유권 확인 후에만 복호화하여 응답. no-store, nosniff 및 서류 강제 다운로드.
- 키 미설정·키 불일치·변조·예상하지 않은 평문 발견 시 오류로 종료. 평문으로 저장하거나 읽는 자동 우회 없음. 빈 값 및 개인정보 없는 고정 기본값은 예외.
- 암호화만으로 계정 접근 권한·주민번호 수집 근거·보존기간 요건이 충족되는 것은 아닙니다.

## 키와 환경 변수
`CARE24_KEY_FILE`에 저장소 밖 키 파일의 절대 경로를 지정합니다. 키 파일 형식은 `{ "active": "k1", "keys": { "k1": "32바이트 키의 base64" } }`입니다. 실제 키를 소스·환경 예시·로그·채팅에 복사하지 않습니다.

`node scripts/prepare-data-key.mjs <저장소 밖 키 파일 경로>`는 기존 파일을 덮어쓰지 않고 키를 생성합니다. Linux는 서비스 계정 소유 0600, 부모 폴더 0700으로 제한합니다. Windows는 서비스 실행 계정/관리 담당자/SYSTEM만 ACL을 부여합니다. 0600 옵션만으로 Windows ACL이 설정된다고 가정하지 않습니다.

키가 없으면 백업도 복구할 수 없습니다. 원래 키를 비밀번호로 보호된 별도 매체나 조직의 비밀정보 보관 시스템에 백업하고, DB 백업과 접근 권한을 분리하세요. GitHub, 공개 웹 폴더, 일반 메일로 보내지 않습니다. 서버 이전 시 기존 암호문을 복구할 수 있는 원래 키를 안전하게 이전해야 합니다. 새 키로 덮어쓰면 기존 자료를 읽을 수 없습니다.

키 교체 시 기존 키 ID를 보존한 채 새 active 키를 추가하고, 복호화 시험·재암호화·백업 복구 시험을 마친 후 기존 키 폐기 여부를 결정합니다. 현재 자동 키 회전 작업은 구성하지 않았습니다.

## 기존 자료 변환
환경 변수 `CARE24_DATABASE_URL`, `CARE24_UPLOAD_DIR`, `CARE24_KEY_FILE`을 설정하고 `node scripts/encrypt-existing-data.mjs`를 실행합니다. 작업 중 사용자 쓰기를 중단하고 서비스 점검 시간을 확보해야 합니다. 스크립트는 `.private/encryption-maintenance`로 새 API DB 요청을 막습니다.

1. 키 검증 후 일관된 SQLite 스냅샷 생성, 암호화 백업의 복호화 일치 확인. 임시 평문 스냅샷 제거.
2. DB 트랜잭션에서 기존 평문 보호 필드 변환 및 비교 검증. 이미 암호화된 값은 검증 후 보존.
3. 첨부파일·메타데이터를 암호화 백업한 뒤 원자적으로 교체. 인식하지 못하는 파일명이나 symlink는 중단.
4. WAL checkpoint/truncate와 VACUUM으로 현재 DB의 잔여 페이지를 정리. 이는 SSD의 삭제 영역, OS 스냅샷, 과거 외부 백업까지 완전 삭제한다는 보장은 아닙니다.
5. 개인정보 없는 건수 보고서 저장. 성공 후 점검 잠금 해제. 실패 시 잠금을 유지하므로 원인을 해결한 뒤 다시 실행합니다.

백업 위치는 `.private/encrypted-backups/<시각>/`. DB 백업의 복호화 AAD는 `backup:database`입니다. 파일 백업 이름은 원래 상대 경로의 SHA256이며, 원래 업로드 경로가 담긴 DB와 함께 복구합니다. 실제 복구는 운영 서비스 중지 후 별도 경로에서 검증하고 수행하세요.

테스트: `node --test tests/encryption.test.mjs`는 합성 자료로 암호문 변조·키 불일치·AAD 변경·백업 복원·재실행을 검증합니다. 로컬 HTTP 검증은 `node --env-file=.env.local --test tests/auth.test.mjs`. `.env.local`은 Git 제외이며 실제 값은 서버의 비공개 설정으로 관리합니다.

## 개인정보처리방침
`/privacy`는 운영자가 제공할 정식 명칭·담당자 연락처·보관 기간·제공/위탁 현황을 기다리는 검토본입니다. 공식 방침 확정과 주민번호·건강정보 등의 수집 근거 확인은 별도 필요합니다. 자동 파기·동의 철회 접수 시스템이 구현됐다고 표시하지 않습니다.
