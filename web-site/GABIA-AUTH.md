# 간병24 일반 로그인 — 가비아 배포 준비

이 소스는 Next.js Node 서버용입니다. 기존 Sites 발행본과 별도로 준비했으며 Cloudflare Worker 배포용이 아닙니다. 기존 D1·R2 자료는 아직 가져오지 않았습니다. 가비아의 기존 MariaDB(dev_db, dolbom, top_comm)는 사용하거나 변경하지 않습니다. 간병24 데이터는 별도의 비공개 SQLite 파일과 업로드 폴더에 저장합니다.

## 구현
- 아이디/비밀번호 가입 신청 → 관리자가 역할과 병원 소속을 확인하고 승인.
- 가입 요청에서 관리자 권한, 승인 상태, 소속 ID를 조작해도 반영하지 않음.
- 관리자: 모든 자료 및 승인/반려/정지/소속 지정. 병원 담당자: 승인된 병원 자료. 간병인: owner_user_id가 본인인 자료.
- 소속/소유자가 없는 기존 자료는 관리자만 열람. 관리자 화면에서 확인 후 연결.
- 비밀번호: 무작위 salt + scrypt N=32768/r=8/p=3. 평문이나 복호화 가능한 비밀번호 저장 없음. 동시 해시 계산 2개, 대기열 제한.
- 세션: 256비트 임의 토큰, DB에는 SHA256 해시만 저장. HttpOnly/SameSite=Lax 쿠키, HTTPS에서 Secure, 8시간 만료. 로그아웃/권한 변경 시 폐기.
- 서버 Origin 검사, 영속 요청 횟수 제한, 승인 상태 매 요청 확인. 모든 업무 API에 서버 권한 검사 및 no-store 적용.
- 업로드: 공개 폴더 밖 저장. 원본 접근에도 해당 자료 소유권 검사. PWA는 업무 화면/API를 오프라인 캐시하지 않음.
- 최초 관리자: samganid5197 / 황세옥. 일반 가입에서 해당 ID 예약. 만료되는 일회용 설정 링크로 사용자가 비밀번호를 직접 설정하며 자동 관리자 승격은 없음.

## 실행
Node 22.13 이상. `npm ci` 후 아래 환경 변수를 지정합니다. 실제 파일은 저장소 밖의 권한 제한 디렉터리를 사용하세요.

```
CARE24_DATABASE_URL=file:/var/lib/care24/care24.db
CARE24_UPLOAD_DIR=/var/lib/care24/uploads
CARE24_KEY_FILE=/etc/care24/data-keyring.json
CARE24_ORIGIN=https://간병24.com에-해당하는-실제-ASCII-호스트
```

CARE24_ORIGIN은 브라우저 Origin과 정확히 같은 스킴/호스트/포트로 설정합니다. 한국어 도메인은 URL 변환 후 ASCII(punycode)를 사용합니다. 실제 도메인/HTTPS 준비 전 이 예시를 운영 값으로 사용하지 마세요.

1. 데이터 폴더를 전용 서비스 사용자 소유로 생성(0700). DB와 업로드 폴더를 웹 정적 경로에 배치하지 않기.
2. `npm run db:migrate:gabia` (새 간병24 DB에서만 실행). 기존 DB를 가져오는 경우 SQLite 백업 및 마이그레이션 이력 매핑을 먼저 준비해야 합니다. 기존 MariaDB에 실행하지 않습니다.
3. `npm run build:gabia`, `npm run start:gabia -- --port 3100`. 외부 노출 없이 127.0.0.1 바인딩. 실제 공개는 TLS reverse proxy 뒤에서만 수행.
4. `node scripts/prepare-admin.mjs`는 관리자 부재 시에만 1시간 설정 링크를 `.private/admin-setup-url.txt`에 기록합니다. 이 파일은 자격 증명입니다. 저장소/로그/공개 파일에 포함하지 않습니다. 설정 완료 후 링크는 사용할 수 없습니다.
5. 관리자가 로그인해 병원을 등록하고 신청 계정의 실제 소속 확인 후 승인합니다. 신청한 병원명과 역할은 참고 정보일 뿐 접근 권한이 아닙니다.

## 검증 및 남은 배포 작업
`tests/auth.test.mjs`는 127.0.0.1:3100의 로컬 서버와 `.private/preview.db` 전용입니다. 합성 테스트 계정/자료만 생성하고 그 ID만 정리합니다. 운영 DB에 실행하지 마세요.

- 7개 자료 종류의 타 병원/동일 병원 타 간병인/미지정 자료 접근 차단.
- 비로그인/승인 대기/위조 헤더/잘못된 Origin 차단.
- 소유권 위조 저장 및 타 병원 수정 차단.
- 가입 승인→로그인→정지 시 세션 폐기, 로그아웃 및 만료 검증.
- 첨부파일 소유권 검사, 비밀번호 해시 검증.

주민번호·계좌번호 등의 보호 필드와 첨부파일 암호화는 구현됐으며 현재 로컬 자료 변환까지 완료했습니다. 키 준비·기존 자료 변환·암호화 백업 절차는 DATA-PROTECTION.md를 따릅니다. 서버로 이전할 때 기존 암호화 키를 안전하게 함께 이전해야 하며 새 키로 덮어쓰면 안 됩니다.

기존 Sites DB/파일 이전, 환자·보호자 접수 정책, 실제 HTTPS 공개 전환은 별도 완료 확인이 필요합니다. 개인정보처리방침은 /privacy에 검토본으로 제공하며 운영 주체·연락처·보관 기간 등을 확인해야 확정할 수 있습니다. 기존 사이트 로그인 제한은 이 소스만 수정해 자동 변경되지 않습니다.
